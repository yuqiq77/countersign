# Tickets

Implementation tickets the owner reads before work starts (v4 §24). One
file per ticket, numbered; each names its ADR, the exact scope, the files
it touches, its tests and the verification it must report.

When a ticket closes, it is condensed for readers into a status line, a
summary, what was built, verification and remaining issues. The working
draft stays in git history, and the closed ticket names the commit that
holds it.
